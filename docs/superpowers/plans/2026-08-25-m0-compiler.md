# M0 Compiler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline execution selected because repository policy disallows subagent dispatch). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the v23.1 deterministic Draft-to-IDF compiler path through M0-013.

**Architecture:** Pydantic schemas separate user/LLM Draft data from fully normalized Compiler input. Resolver is the exclusive normalization boundary; compiler modules deterministically create canonical epJSON, then a toolchain adapter converts and validates artifacts.

**Tech Stack:** Python 3.11, Pydantic v2, standard-library unittest, EnergyPlus v23.1 CLI.

**Spec:** `docs/superpowers/specs/2026-08-25-m0-compiler-design.md`

## Global Constraints

- EnergyPlus is fixed at v23.1; use only `EPLUS_PATH` via `idfgenx.config`.
- Compiler accepts only `ResolvedScenarioSpec`; no real AirLoopHVAC, PlantLoop or device topology.
- All production interfaces have Chinese docstrings and explicit type annotations.
- Snapshot data and `data/releases` are read-only; each conversion uses an isolated work directory.
- New behavior follows failing-test → minimal implementation → passing-test cycles.
