# AI 执行报告

每个修改项目的 AI 任务完成后必须在本目录生成一份 Markdown 报告。报告是“实际发生了什么”的证据，不是任务计划的复制。

## 命名

```text
YYYY-MM-DD-<task-id>-<short-slug>.md
```

例如：

```text
2026-08-21-IDFGX-M0-001-scenario-spec-v0.1.md
```

## 必填内容

- 对应任务和范围；
- 实际修改文件；
- 关键实现与设计偏差；
- 实际运行的验证命令和结果；
- 未完成项、已知风险和后续建议；
- 数据/Schema/API/模型兼容性影响；
- commit、PR、数据 release、模型或评估 run ID。

## 规则

1. 不粘贴数千行原始日志，只保留摘要和关键错误；
2. 不写密钥、完整敏感 Prompt、用户路径或大文件内容；
3. 失败或部分完成也要如实报告，任务状态不得伪装为 `done`；
4. 报告发布后若需更正，在底部追加 correction，不静默重写历史结论；
5. 多个代理处理同一任务时合并为一份主报告，并列出各自工作；
6. 报告中的“通过”必须对应本次实际执行的命令。
