# IDFGX-X-001 执行报告：共享配置与错误骨架

## 1. 结果摘要

已建立 `idfgenx.config` 与 `idfgenx.errors`，为后续 Schema、Resolver、Compiler、Validator 和服务提供唯一基础配置与错误边界。配置只识别 `EPLUS_PATH` 和 `ENERGYPLUS_VERSION`，固定 EnergyPlus 23.1，不在导入时访问环境或文件系统。Python 项目约束与 uv 锁文件已收敛到 3.11；9 项相关测试和全量 27 项单测通过。

## 2. 实际变更

| 文件/目录 | 变更 |
| --- | --- |
| `idfgenx/config.py` | 新增不可变配置模型与显式环境映射加载函数 |
| `idfgenx/errors.py` | 新增统一错误码、项目异常基类和配置异常 |
| `idfgenx/__init__.py` | 导出稳定共享基础接口，保持导入无配置副作用 |
| `tests/unit/test_config.py` | 覆盖规范变量、默认值和固定版本拒绝 |
| `tests/unit/test_errors.py` | 覆盖错误载荷、上下文、cause 和配置分类 |
| `tests/unit/test_package_contract.py` | 覆盖包根稳定导出 |
| `pyproject.toml`、`uv.lock` | 固定 Python `>=3.11,<3.12` 并收敛锁文件 |

## 3. 关键实现

- `load_config()` 支持注入只读环境映射，使单测与宿主环境隔离；
- `IDFGenXConfig` 直接构造与加载入口共用 23.1 版本不变量，注入路径不展开宿主用户目录；
- 配置层只规范化值，不检查 EnergyPlus 路径或可执行文件，健康检查留给 M0-004；
- `IDFGenXError` 保留稳定错误码、消息、深复制上下文和异常 cause；
- 错误载荷不含 HTTP 状态码，避免领域层绑定 FastAPI；
- 未迁移 `server/` 现有环境读取和仿真代码，保持本任务最小边界。
