# AI 任务记录

每个会修改项目的任务使用一个稳定文件：`<task-id>-<short-slug>.md`。文件不随状态移动，避免报告、提交和其他任务中的链接失效。

## 维护规则

1. 从 `TASK-TEMPLATE.md` 创建任务；
2. `task_id` 必须能在 `MASTER_PLAN.md` 找到，临时跨模块任务使用 `IDFGX-X-NNN`；
3. 一个任务只产生一个明确、可验证的主要结果；
4. 任务应列出精确文件和命令，不写“完善相关代码”之类模糊步骤；
5. 状态变化必须更新时间和原因；
6. `done` 必须链接至少一个报告；
7. 阻塞不等于失败，必须记录已经验证的事实和解除条件；
8. 被替代的任务标记 `canceled`，并链接替代任务。

## 粒度

- 一个任务通常控制在半天到两天；
- 每个执行步骤应能在 5–30 分钟内验证；
- 超过两天或跨多个模块时先拆分；
- 数据构建、训练和评估运行可以持续更久，但准备、执行、分析应拆成独立步骤。
